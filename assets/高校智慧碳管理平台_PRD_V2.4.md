# 1. 项目背景与机会

## 1.1 课题背景

本项目隶属"数智能碳课题组"，课题目标为：

- 面向北京市重点碳排放单位中的**医院和学校**，研究覆盖**数据采集→数据质量管理→碳排放核算→排放分析→减排路径→碳管理→碳资产管理→监督考核→示范创建**的全链条服务体系。
- 完成一套行业化解决方案、一份汇报材料和一个**轻量可演示的系统**。
- 利用虚拟样例数据展示核心指标、建设成效和四层控制塔效果。

**一期聚焦高校场景**，医院为后续扩展。采用虚拟高校客户，使用模拟数据，三周完成 Demo 开发。

## 1.2 产品定位

高校智慧碳管理平台**不是**通用"碳计算器"，而是一套以真实高校为客户原型、覆盖**数据采集→质量控制→核算报告→核查整改→配额履约→减排项目→监督评价**全过程的碳管理数字化平台。

它连接计量、账单、资产、建筑和组织数据，以可追溯核算为基础，通过**四层控制塔体系**向不同层级用户提供精准视图：校领导掌握全校零碳建设总览，院系负责人管理本部门碳绩效，后勤运维处理日常监控与异常，合规人员完成报送与审计溯源。并通过**AI 智能分析中心**提供预测性分析、异常报警、减排路径优化和智能体政策咨询能力。

## 1.3 业务目标与价值主张

### 北极星目标

> **让校方在任意时点回答四个问题：数据是否可信？排放从哪里来？年底是否会超配额？优先做什么项目最划算？**

### 业务目标（OKR 框架）

| Objective | Key Result | 量化目标 | 验证方式 |
|---|---|---|---|
| 让排放数据可见、可信 | 所有核算结果可追溯到活动数据、因子版本和支撑材料 | 抽样追溯成功率 100% | 随机抽样追溯测试 |
| 让管理流程闭环可控 | 每个重大异常可转为整改/减排项目并跟踪成效 | 闭环状态链覆盖率 ≥ 95% | 闭环流程演示验证 |
| 让履约决策有据可依 | 按情景预测配额缺口和资金敞口，展示关键日期 | 情景预测偏差 ≤ 15%（模拟数据校验） | 资产页面测试 |
| 让校领导快速掌握全局 | 校领导在碳控制塔 3 分钟掌握总量、强度、目标、风险与重点问题；各层用户通过对应视图高效履职 | 控制塔各层任务测试 ≤ 3 分钟 | 四层控制塔任务测试 |

## 1.4 现状痛点分析

北京市重点碳排放单位承担月度数据、年度排放报告、第三方核查、配额管理与清缴等责任。高校同时具有多校区、多建筑、多能源、多业务场景和寒暑假波动等特征，单纯依靠账单和 Excel 难以形成稳定、可审计的数据链。

| 痛点 | 典型表现 | 业务后果 |
|---|---|---|
| 数据分散 | 后勤、财务、物业、供能单位各自留存表计、账单和合同 | 口径不一、重复填报 |
| 边界复杂 | 校区、家属区、出租商户、校办企业、共用设施边界模糊 | 漏算、重算、核查争议 |
| 质量滞后 | 年末集中补数，缺失和突变无人闭环 | 报告返工、履约风险 |
| 分析失真 | 未考虑建筑类型、面积、人数、气象和校历 | 难以判断"高耗能"是否异常 |
| 项目脱节 | 节能改造立项与排放台账、财务收益分离 | 减排成效无法证明 |
| 资产被动 | 只在清缴前核对配额和排放 | 采购时点与资金安排被动 |

## 1.5 政策事实基线（产品配置依据）

- 2026 年北京市重点碳排放单位须在每月结束后 **20 个自然日**内上报月度数据及支撑材料。
- 2026 年 **3 月 31 日**前报送上一年度碳排放报告，**4 月 30 日**前报送经核查排放报告和第三方核查报告。
- 2026 年 **7 月 31 日**前完成排放量确认和免费配额核定发放；**9 月 30 日**前提交抵销申请；**10 月 31 日**前完成清缴。
- 数据原始记录和管理台账等材料至少保存 **5 年**；重点单位应制定、报告并实施数据质量控制方案。
- 低碳校园评价关注碳排放强度、低碳管理、低碳文化和低碳运行，并要求重点高校按时报送、核查和履约。
- **JS/T 303-2026《公共机构碳排放核算指南》**：国管局发布的公共机构碳排放核算标准，覆盖范围 1 和范围 2，采用"能源消耗量×综合排放因子"方法，参数合并计算更简便，适合公共机构统一统计和日常碳管理。上报周期一般按年度。
- **DB11/T 1785-2020《二氧化碳排放核算和报告要求 服务业》**：北京市地方标准，覆盖范围 1 和范围 2，采用"热值→含碳量"法，逐项展开热值、含碳量、氧化率等参数，数据要求更细，更便于监测、核查和追溯。
- **DB11/T 2223-2024《公共机构能源资源消费统计管理规范》**：北京市地方标准，规范公共机构能源资源消费的统计口径、数据采集和上报流程，为碳核算提供基础能源统计数据支撑。
- **GB/T 29117-2012《节约型学校评价导则》**：国家标准，从节能、节水、节地、节材、环境保护等维度建立节约型学校评价指标体系，用于评价学校在资源节约方面的综合表现，是绿色/低碳校园申报评价的核心参考标准之一。
- **GB/T 51356-2019《绿色校园评价标准》**：国家标准，从能源资源利用、校园运行管理、低碳技术应用、宣传教育机制等维度建立绿色校园评价指标体系（含评分制和评价等级），是绿色校园申报评价的核心参考标准之一。

> **两项碳排放核算标准的关系说明**：JS/T 303-2026 与 DB11/T 1785-2020 核算对象大体相同（范围 1 + 范围 2）、基本原理相同（均为活动数据×排放参数）。JS/T 303 把若干参数合并成一个综合排放因子，计算更简便，更适合公共机构统一统计和日常碳管理；DB11/T 1785 把热值、含碳量、氧化率逐项展开，数据要求更细，更便于北京市服务业精细监测与规范报告。二者可以衔接使用（如 DB11/T 1785 的细分参数可为 JS/T 303 的综合因子提供溯源支撑），但不能简单视为完全相同或相互替代。平台支持两种方法并行核算、结果对比。

> **两项绿色/低碳校园评价标准的关系说明**：GB/T 29117-2012 侧重节约型学校的通用评价（节能、节水、节地、节材、环保），GB/T 51356-2019 侧重绿色校园的专项评价（能源资源利用、校园运行管理、低碳技术应用、宣传教育机制），采用百分制评分和评价等级制度。两项标准评价对象重合但侧重不同，平台综合引用两项标准，在大看板中同时展示两套指标体系的达标情况。

> ⚠️ 上述日期是 2026 年度配置样例。产品必须提供政策日历后台，支持年度更新和有效期管理。所有排放因子、配额、价格及政策期限均须按年度配置，禁止硬编码。

## 1.6 为什么现在做

- 北京市碳市场持续收紧，高校作为重点排放单位的合规压力逐年增加。
- "双碳"战略下，公共机构节能降碳成为政策抓手，低碳校园评价标准已发布。
- 课题组需要在三周内产出可演示成果，为后续正式项目打下基础。

# 2. 需求概述

## 2.1 用户痛点总结

1. **看不到**：排放数据分散在多个系统和人员手中，领导无法实时掌握全局。
2. **算不准**：核算口径不统一、因子版本混乱、数据质量无法保证。
3. **管不住**：异常发现滞后、责任不清、整改无闭环。
4. **报不出**：年底集中整理数据，报告质量差、核查问题多。
5. **履约被动**：不清楚配额缺口、无法提前规划资金和交易策略。
6. **评不了**：低碳校园自评缺乏数据支撑和材料归集。

## 2.2 预期收益

| 维度 | 预期收益 | 量化指标 |
|---|---|---|
| 管理效率 | 从"年底突击"变为"日常管控" | 数据完整率 ≥ 98% |
| 合规保障 | 关键节点按时完成 | 报告/核查/清缴按时率 100% |
| 节能减排 | 异常可定位、减排可量化 | 异常关闭率 ≥ 90% |
| 决策支撑 | 校领导 3 分钟掌握全局，各层用户高效履职 | 四层控制塔任务测试 ≤ 3 分钟 |
| 资产优化 | 提前预警配额缺口 | 提前 ≥ 90 天预警 |

## 2.3 版本范围

- **本版本（V2.1 / MVP）**：三周 Demo，聚焦高校场景，四层控制塔 + AI 智能分析中心 + 5 个核心功能页面（共 10 个演示页面），虚拟数据驱动。
- **V2.0 不含**：真实设备对接、政府平台自动申报、交易所下单、移动端完整功能、等保测评。

# 3. 用户需求与功能需求

## 3.1 用户角色定义

### 角色 1：校领导

| 属性 | 描述 |
|---|---|

| 属性 | 描述 |
|---|---|

**User Story**：作为学院院长，我希望看到本学院的碳排放排名和减排任务完成进度，以便主动推动院内节能管理并认领减排责任。

# 4. 业务流程

## 4.1 端到端业务闭环

| 阶段 | 输入 | 系统动作 | 输出/状态 |
|---|---|---|---|
| 1 主数据准备 | 组织、校区、建筑、设施、表计、责任人 | 边界校验、有效期管理 | 可核算边界 |
| 2 数据采集 | 接口读数、账单、手工表、光伏数据 | 落原始区、去重、单位换算 | 待校验数据 |
| 3 质量控制 | 规则、历史、校历、气象、账单总量 | 完整性/合理性/一致性检查 | 通过、警告、阻断 |
| 4 碳核算 | 合格活动数据、因子、方法版本 | 按排放源计算并汇总 | 月度/年度排放清单 |
| 5 报告核查 | 报告模板、支撑材料、核查问题 | 生成、锁定、问题整改 | 报告版本、核查结论 |
| 6 分析预警 | 实绩、预算、目标、基线、校历 | 趋势、对标、预测、告警 | 问题清单 |
| 7 减排项目 | 异常、措施库、成本参数 | 方案测算、审批、MRV | 项目台账与实绩 |
| 8 碳资产 | 确认排放、配额、抵销量、价格情景 | 缺口/盈余和资金敞口预测 | 履约方案与清缴台账 |
| 9 监督评价 | 目标、任务、证明材料、评分规则 | 自评、差距、整改闭环 | 考核包/创建材料 |

### 四条核心闭环

1. **数据闭环**：数据异常 → 责任工单 → 复核关闭
2. **履约闭环**：排放预测 → 配额缺口 → 履约方案 → 清缴归档
3. **减排闭环**：异常/目标差距 → 减排项目 → MRV → 效益复盘
4. **评价闭环**：评价失分 → 整改任务 → 证据上传 → 重新自评

## 4.2 核心状态流转

### 活动数据状态
```
草稿 → 已提交 → 已复核 → 已锁定
                      ↑
            （回退须填写原因）
```

### 核算批次状态
```
试算 → 复核中 → 已锁定 → 经核查 → 已确认
                  ↑
       （解锁需申请审批，不覆盖原版本）
```

### 质量问题/工单状态
```
待确认 → 已分派 → 处理中 → 待复核 → 已关闭 / 误报
```

### 项目状态
```
建议 → 论证 → 已批准 → 实施中 → 已验收 → 运行评估 → 归档
```

### 报告版本状态
```
草稿 → 复核中 → 已锁定 → 经核查 → 已确认
```

## 4.3 正常流程示例：月度数据上报

1. 每月结束后 20 个自然日内，数据填报员导入/填报当月能耗数据。
2. 系统自动执行质量规则校验（完整性、合理性、一致性）。
3. 校验通过的数据进入"已复核"状态；校验不通过的生成异常工单。
4. 能源管理员处理异常工单，补充材料或修正数据。
5. 碳管理员确认数据质量达标后，执行核算计算。
6. 核算结果复核无误后锁定，生成月度排放清单。

## 4.4 异常流程处理

| 异常场景 | 处理方式 |
|---|---|
| 账单与表计差异超阈值 | 进入"待解释"状态，责任人补充说明 |
| 数据缺失超过容忍度 | 阻断锁定，要求补录或标记估算方法 |
| 绿电凭证量不足 | 回退至适用电力因子并告警 |
| 因子版本变更 | 不静默重算历史；用户选择"沿用"或"生成重算版本" |
| 已锁定周期需修改 | 走解锁审批流程，保留前后版本 |
| 阻断级质量问题存在 | 禁止锁定，列出问题清单 |

## 6.2 核算边界与方法

### 组织与运营边界

- 默认采用法人边界：纳入某大学在北京市行政区域内控制运营的固定设施。
- 按"学校—校区—建筑—区域—设施—计量点"建立空间层级。
- 出租、家属区、校办企业和共用能源站标注纳入/排除及分摊规则。
- 边界变化须记录生效日期、依据材料和对基准/配额的影响。

### 一期排放源

| 类别 | 活动数据 | 典型来源 | 一期处理 |
|---|---|---|---|
| 固定燃烧 | 天然气等燃料消耗量 | 燃气表、账单 | 活动量×低位热值×单位热值含碳量×氧化率×44/12 |
| 外购电力 | 购入/使用电量、绿电凭证 | 电表、账单、交易凭证 | 火电与绿电分开；因子按年度版本配置 |
| 外购热力 | 购热量 | 热量表、结算单 | 购热量×适用热力排放因子 |
| 光伏 | 发电、上网、自用量 | 逆变器/结算单 | 作为能源结构与减排贡献展示，不与购电重复扣减 |
| 其他 | 水、车辆、废弃物等 | 台账 | P1 扩展指标，不计入一期履约核心结果 |

### 两种碳排放核算方法对比

平台支持两种互补的碳排放核算方法，对同一核算对象（范围 1 + 范围 2）进行并行计算，结果可对比。

| 对比维度 | JS/T 303-2026《公共机构碳排放核算指南》 | DB11/T 1785-2020《二氧化碳排放核算和报告要求 服务业》 |
|---|---|---|
| 发布机构 | 国管局 | 北京市质监局 |
| 适用范围 | 全国公共机构 | 北京市服务业（含高校） |
| 核算范围 | 范围 1（固定燃烧 + 移动燃烧 + 逸散）+ 范围 2（外购电力 + 外购热力） | 范围 1（固定燃烧 + 移动燃烧 + 逸散）+ 范围 2（外购电力 + 外购热力） |
| 核算方法 | **综合排放因子法**：排放量 = 能源消耗量 × 综合排放因子 | **热值含碳量法**：排放量 = 燃料热值 × 单位热值含碳量 × 碳氧化率 × 44/12 |
| 参数粒度 | 参数合并为综合排放因子，一层计算 | 热值、含碳量、氧化率逐项展开，多层计算 |
| 数据要求 | 相对简便，适合统一统计 | 数据要求更细，适合精细监测与核查追溯 |
| 适用场景 | 公共机构日常碳管理、年度碳盘查、统一上报 | 北京市服务业排放监测、核查、规范报告 |
| 上报周期 | 一般按年度上报 | 按北京市要求上报 |
| 二者关系 | 可衔接使用，DB11/T 1785 的细分参数可为 JS/T 303 的综合因子提供溯源支撑 | 不能简单视为完全相同或相互替代 |

> **能源统计规范衔接**：DB11/T 2223-2024《公共机构能源资源消费统计管理规范》为碳核算提供基础能源统计数据支撑，规范能源消费统计口径和数据采集流程。其统计的能源实物量数据是两种核算方法的共同数据基础。

### 核算规则

- **基础公式（JS/T 303 综合因子法）**：排放量 E = Σ(能源消耗量 × 综合排放因子 EF)
- **基础公式（DB11/T 1785 热值含碳量法）**：排放量 E = Σ(燃料消耗量 × 低位热值 × 单位热值含碳量 × 碳氧化率 × 44/12) + 外购电力/热力对应排放
- 系统同时保存输入值、单位、换算过程、参数来源、参数有效期、公式版本、计算时间和计算人/任务。
- 同一计量周期只允许一个生效数据版本；账单与表计差异超过阈值进入待解释状态。
- 缺失值可临时估算，但必须标记估算方法、置信等级和替换期限。
- 绿电"零排放"仅在满足当年政策与凭证要求时适用。
- 因子变更不得静默重算历史。
- 预测排放不进入正式报告。
- 两种核算方法共用同一套底层活动数据，但分别使用各自的参数体系和公式版本，计算结果独立存储、可对比。

### 6.4.5 四层联动逻辑

四层控制塔不是四个孤立页面，而是一套自上而下穿透、自下而上汇总、权限隔离、AI 预警全局同步的有机体系。

#### 1. 自上而下穿透

| 穿透路径 | 说明 |
|---|---|
| L1 → L2 | 校领导控制塔任意宏观指标（如某校区排放总量、某学院排名）可点击下钻至 L2 对应院系业务视图 |
| L2 → L3 | 院系视图中高耗能点位、异常提示可继续穿透至 L3 运营明细（具体楼栋/设备/计量点） |
| L3 → L4 | 运营明细中任意数据点可溯源至 L4 合规视图查看原始凭证和审计轨迹 |
| 全链路 | L1 宏观指标 → L2 部门绩效 → L3 明细数据 → L4 原始凭证，一条链路贯穿 |

#### 2. 自下而上汇总

| 汇总路径 | 说明 |
|---|---|
| L3 → L2 | 底层运营数据（分楼栋/分项能耗）自动按组织归属汇总至对应部门绩效指标 |
| L2 → L1 | 各部门绩效自动聚合为全校宏观指标（总排放、人均能耗、单位面积排放等） |
| L3/L4 → 合规层 | 合规层留存全部原始凭证，不受上层汇总规则影响 |
| 数据一致性 | 所有层级使用同一套源数据和指标服务，总量=各分项之和，允许因未分摊公共项产生可解释差异 |

#### 3. 权限隔离

| 层级 | 默认权限 | 特殊规则 |
|---|---|---|
| L1 校领导控制塔 | 校级领导、校发展规划处、上级演示账号 | 可查看全部宏观数据，下钻至 L2 全部院系 |
| L2 院系业务视图 | 各院系/部门负责人 | 仅可见本部门数据 + 同类型横向对比（脱敏），校领导可切换至任意院系 |
| L3 后勤运营明细 | 后勤运维、能源管理员 | 可见全部楼栋/设备级明细数据 |
| L4 合规与披露 | 审计处、合规专员、碳管理员 | 可见全量数据及审计轨迹，核查账号只读限年度/范围 |
| 跨层访问 | — | 四层视图配置分级账号权限，未授权层级显示"权限不足"及申请路径 |

#### 4. AI 预警全局同步

| 联动规则 | 说明 |
|---|---|
| L3 识别异常 | 运营明细层异常告警中心识别到异常（如夜间空载、用气超标） |
| → L1 风险板块 | 异常自动同步至校领导控制塔"重大风险预警"区域，按严重级别排序 |
| → L2 扣分标记 | 异常在对应院系业务视图中标记扣分影响，影响部门排名和考核得分 |
| → L4 审计留痕 | 异常事件及处置全过程在合规视图中留存审计轨迹 |
| 闭环确认 | 异常在 L3 关闭后，L1 风险卡自动更新状态，L2 扣分标记解除 |

### 页面 1E：AI 智能分析中心（P0 演示能力）

**用户任务**：全体用户通过 AI 智能分析中心获取预测性分析、实时异常告警、减排路径优化建议和政策合规咨询，实现从被动响应到主动预警的管理升级。

#### 模块 1：预测性分析

**界面布局**：

| 区域 | 组件与交互 | 演示重点 |
|---|---|---|
| 排放趋势预测 | 基于历史数据+校历+气象的未来 30/60/90 天排放趋势预测曲线（含置信区间） | 预测与实绩区分 |
| 节假日调控预案 | 寒暑假、国庆、春节等节假日自动生成的动态调控预案卡片（含预计节能量/减排量） | 自动触发 |
| 超标预警 | 提前预警可能超标的时段和区域（热力日历形式），标注触发条件和影响范围 | 红色高亮 |
| 情景模拟器 | 不同调控策略（如空调温度调高 1°C、夜间断电范围扩大）下的排放/能耗预测对比折线图 | 假设可调 |

**交互设计**：

- 预测曲线基于历史数据+校历+气象模型生成，标注"AI 预测，仅供参考"。
- 节假日预案在对应假期前 30 天自动生成，用户可修改参数后重新生成。
- 情景模拟器支持同时对比 2-3 种策略，实时刷新预测曲线。
- 预测结果可一键推送至 L1 控制塔风险板块和 L2 对应院系视图。

#### 模块 2：实时监控异常报警

**界面布局**：

| 区域 | 组件与交互 | 演示重点 |
|---|---|---|
| 实时数据流监控 | 全校能耗/碳排放实时数据流大屏（动态刷新），支持按校区/楼栋/能源类型筛选 | 动态效果 |
| 异常自动识别 | AI 自动识别异常模式（突增、空载、超标、偏移），按严重级别（阻断/严重/一般/提示）分级展示 | 分级告警 |
| 告警推送中心 | 站内消息列表 + 短信/邮件推送接口预留（标注 P2 实现），支持标记已读/忽略/转工单 | 推送机制 |
| 异常事件时间线 | 按时间轴展示异常事件流（发现→确认→处置→关闭），支持筛选和搜索 | 全生命周期 |
| 影响范围评估 | 每条异常的影响范围估算（涉及建筑/人数/预计额外排放/费用影响） | 影响量化 |

**交互设计**：

- 异常告警与 L3 运营明细视图双向联动：AI 中心识别的异常同步出现在 L3 告警中心，L3 手动录入的异常也同步到本模块。
- 告警支持一键转工单（关联 L3 运营明细）或转 AI 减排建议（模块 3）。
- 异常事件时间线支持点击展开详情，查看 AI 识别依据和置信度。

#### 模块 3：AI 减排空间与路径优化

**界面布局**：

| 区域 | 组件与交互 | 演示重点 |
|---|---|---|
| 减排空间分析 | 各建筑/院系的减排潜力量化排名（基于基准线对比、设备效率、运营优化空间），气泡图展示 | 减排机会可视化 |
| 减排路径优化 | 多措施组合的最优路径推荐（考虑投资、回收期、减排量、实施难度），甘特图展示推荐实施顺序 | 路径可视化 |
| 碳配额关联优化 | 减排+配额采购+抵销的综合成本最优策略对比（总成本曲线+组合方案卡片） | 成本最优 |
| 措施详情 | 每条措施的实施步骤、前置条件、风险、MRV 方法（整合原 F-07 AI 减排策略中心内容） | 可执行方案 |

**交互设计**：

- 减排空间分析支持按建筑/院系/能源类型切换维度。
- 路径优化支持用户调整约束条件（如年度预算上限、最短回收期要求），系统重新计算最优组合。
- 碳配额关联优化整合碳资产管理页面数据，展示"先减排后采购"与"直接采购"的成本对比。
- 本模块整合原 AI 减排策略中心（F-07）的核心能力，原 F-07 页面（页面 4）作为简化版保留，本页面提供更全面的分析。

**与原页面 4（AI 减排建议）关系**：页面 4 侧重单异常的单措施建议快速交互，本页模块 3 侧重全校减排空间分析和多措施组合路径优化。页面 4 的单条建议可跳转至本模块查看该措施在全局路径中的位置。

#### 模块 4：政策咨询与合规 AI 助手（智能体接入）

**界面布局**：

| 区域 | 组件与交互 | 演示重点 |
|---|---|---|
| 对话式交互 | 类聊天窗口的自然语言问答界面，支持上下文连续对话 | 智能体交互 |
| 快捷问题模板 | 预设常用问题：月度报告截止日期、绿电凭证核算方法、配额清缴流程、DB11 标准解读 | 快速入口 |
| 合规检查辅助 | 自动对照最新政策检查当前数据/报告的合规状态清单（红绿灯），支持一键跳转修复 | 合规体检 |
| 政策变更提醒 | 当北京碳市场政策更新时，显示受影响的管理流程列表和建议操作 | 变更追踪 |
| 回答溯源 | 每条 AI 回答标注引用来源（政策文件/标准条款/系统配置），支持点击查看原文 | 可溯源 |

**交互设计**：

- 智能体接入方式：Demo 中模拟大模型回复效果，标注"AI 回答仅供参考，请以正式政策文件为准"。
- 支持自然语言查询示例："本月月度报告截止日期是什么时候？""绿电凭证怎么核算？""教学楼 A 的排放核算用了哪个因子？"

### 6.4.6 跨层穿透 UI 交互规则

四层控制塔的跨层穿透不仅是数据层面的贯通，更需要在 UI 层面提供一致的视觉引导和交互体验。

#### 1. 全局下钻链路 UI 表现

| 穿透路径 | 3D 场景 UI 表现 | 跳转目标 |
|---|---|---|
| L1 → L2 | L1 指标/风险点击 → 3D 楼栋闪烁定位 → 自动跳转 L2 院系驾驶舱 | L2 对应院系视图 |
| L2 → L3 | L2 楼栋弹窗/排名点击 → 3D 镜头聚焦目标楼栋 → 自动跳转 L3 运营明细 | L3 对应楼栋明细 |
| L3 → L4 | L3 告警/设备点击 → 3D 定位建筑 → 自动跳转 L4 审计视图 | L4 对应楼栋审计 |
| AI → L1-L4 | AI 中心异常标记 → 3D 场景闪烁 → 一键跳转对应层级 | 异常关联层级 |

#### 2. 筛选上下文保持

- 页面切换时保留筛选上下文（年份、校区、核算状态不变）。
- 下钻时自动继承上层筛选条件，并在目标页面顶部筛选栏高亮显示已继承的筛选项。
- 用户可在目标页面修改筛选条件，修改后不影响原层级页面状态。
- 返回上层时恢复原层级页面的筛选状态。

#### 3. 权限 UI 控制

| 规则 | 说明 |
|---|---|
| 不可查看指标 | 低权限账号隐藏不可查看的指标卡片，不展示空卡片或占位 |
| 不可操作按钮 | 底部跳转按钮置灰（例：院系负责人无法查看全校横向对标卡片，底部无跳转 L1 按钮） |
| 权限提示 | 置灰按钮悬浮显示"权限不足，请联系管理员开通" |
| 审计记录 | 所有权限拦截操作生成审计日志 |

### 页面 3：碳核算工作台（P0）

**页面名称**：碳核算工作台
**页面定位**：面向碳管理员、节能办专员、后勤能源管理员、审计/核查专员，以**年度上报和年度监控**为目的的碳排放核算工作台。
**适配标准**：
1. JS/T 303-2026《公共机构碳排放核算指南》——综合排放因子法
2. DB11/T 1785-2020《二氧化碳排放核算和报告要求 服务业》——热值含碳量法
3. DB11/T 2223-2024《公共机构能源资源消费统计管理规范》——能源统计数据基础
4. GHG Protocol、ISO 14064-1

**核心用户**：碳管理员、节能办专员、后勤能源管理员、审计/核查专员、院系管理员

**核心目标**：统一管理全校园数据源、双方法自动核算（综合因子法 vs 热值含碳量法）、多维度可视化看板、一键生成合规上报材料、全链路 MRV 溯源、与四层 3D 碳控制塔双向数据互通。

**上报周期**：一般按照年度上报。

#### 3.1 迭代背景

原碳核算工作台仅具备基础数据录入、简单计算能力，存在 3 项核心缺失：

1. 无标准化数据源分层管理与可视化看板，数据统计、能耗分析、合规核查需要人工导出 Excel 二次加工，效率极低；
2. 未区分 JS/T 303 和 DB11/T 1785 两种互补核算方法，核算逻辑混杂，产出材料无法直接用于官方报送；
3. 工作台与四层 3D 碳控制塔数据割裂，数值易出现不一致，无法实现从宏观大屏下钻至底层台账的完整溯源链路。

本次迭代整合**数据源看板完整细化方案**+**双方法自动核算+合规报告导出功能**，实现：统一数据源分类管理、多维度可视化分析、两种互补核算方法独立核算引擎、成套带附件成品报告一键打包下载、全链路 MRV 审计、和 L1-L4 三层 3D 驾驶舱数据双向打通，完全满足高校年度碳盘查、第三方核查全合规场景。

#### 3.2 核心业务目标

1. **数据源标准化**：完全匹配 S-A01~S-A19 高校数据源清单，搭建统一分类体系，覆盖边界、能源、扩展排放、核算支撑全维度数据；
2. **可视化分析**：4 套专用看板分别满足全局统计、能源减排分析、Scope3 专项、凭证审计四大场景；
3. **双方法互补核算**：同一核算数据支持 JS/T 303（综合排放因子法）和 DB11/T 1785（热值含碳量法）两种方法可选/并行，独立计算、结果对比、分批次存储；
4. **一键出报**：自动生成对应核算方法的成套 Excel 报表 + 佐证附件，支持单文件/压缩包下载，可直接对外报送；
5. **全域数据互通**：工作台与四层 3D 碳控制塔同源数据，支持自上而下下钻、自下而上溯源。

#### 3.3 页面整体结构

| 方法标识 | 文件名称 | 适用场景 | 核心核算差异 |

| 方法 A | JS/T 303-2026《公共机构碳排放核算指南》 | 年度碳盘查、碳中和申报、配额履约、低碳校园自评 | 综合排放因子法：排放量 = 能源消耗量 × 综合排放因子；区分 Scope1/2 核心排放，Scope3 仅附表披露；光伏、绿证、碳汇单独列示减排量，不直接抵扣总排放；强制配套全链条 MRV 凭证附件 |
| 方法 B | DB11/T 1785-2020《二氧化碳排放核算和报告要求 服务业》 | 北京市服务业碳排放监测、核查、规范报告 | 热值含碳量法：排放量 = 燃料消耗量 × 低位热值 × 单位热值含碳量 × 碳氧化率 × 44/12；参数逐项展开，数据要求更细，便于精细监测与核查追溯；适用于北京市服务业上报 |

> **两种方法的关系**：核算对象大体相同（范围 1 + 范围 2）、基本原理相同。JS/T 303 把若干参数合并成综合排放因子，计算更简便；DB11/T 1785 把热值、含碳量、氧化率逐项展开，数据要求更细。二者可以衔接使用，但不能简单视为完全相同或相互替代。平台支持两种方法对同一核算数据并行计算、结果对比。

## 6.7 AI 能力边界与治理

| 允许 | 禁止 |
|---|---|
| 将规则命中的事实组织成解释文本 | 虚构表计、账单、因子、价格或政策 |
| 从审核过的措施库匹配候选措施 | 未经确认直接修改核算结果或锁定状态 |
| 基于显式假设进行节能与经济性试算 | 声称相关性即因果、保证节能收益 |
| 生成报告草稿、问题摘要和汇报提纲 | 替代第三方核查、正式评价或审批结论 |
| 记录引用数据、知识条目、模型版本 | 自动控制设备、自动交易或对外报送 |
| 基于历史+校历+气象进行排放趋势预测 | 预测值进入正式报告或作为履约依据 |
| 自动识别异常模式并分级告警 | 自动关闭告警（需人工确认） |
| 推荐多措施组合的减排路径 | 自动执行减排措施或自动调整设备 |
| 接入智能体提供政策问答和合规参考 | 自动生成正式合规报告或替代核查结论 |

**治理要求**：

- 每次 AI 输出保存输入数据范围、知识库版本、模型版本、提示模板版本和用户反馈。
- 对低置信度、数据缺失或超出措施库覆盖的情况，系统应明确说"不足以判断"。
- 金额、减排量和回收期由确定性计算服务生成；大模型仅负责解释，不负责心算。
- 输出中不得包含学生个人信息；默认只使用建筑、设施和聚合运营数据。

**智能体接入治理要求**：

- 政策咨询 AI 助手（智能体）的回答必须标注引用来源（政策文件名称+条款编号+生效日期），用户可点击查看原文。
- 智能体不得自动生成正式报告、替代第三方核查结论或修改系统业务数据。
- 智能体的政策知识库须按年度更新，由碳管理员审核确认后生效。
- 智能体回答的置信度低于阈值时，必须明确回复"无法确认，建议查阅正式政策文件或咨询主管部门"。
- 智能体接入须记录所有问答日志（用户问题、AI 回答、引用来源、用户反馈），保存期限不少于 5 年。

## 6.8 数据质量管理设计

| 规则类型 | 示例 | 结果 |
|---|---|---|
| 完整性 | 应到 24 个小时点但仅 22 个；账单附件缺失 | 警告/阻断 |
| 格式与单位 | kWh/MWh 混用、负数、日期跨期 | 阻断 |
| 合理性 | 单点超设备容量、日环比突增 50% | 告警 |
| 一致性 | 分表和≠总表；表计累计量与账单差异超阈值 | 待解释 |
| 时序与业务 | 寒暑假教学楼负荷未下降；夜间基载异常 | 告警 |
| 凭证有效性 | 绿电凭证量小于申报绿电量；校准证书到期 | 阻断/提醒 |

**质量管理机制**：

- 质量问题状态：待确认 → 已分派 → 处理中 → 待复核 → 已关闭/误报；所有状态留痕。
- 严重级别：阻断、严重、一般、提示；只有阻断问题会阻止周期锁定。
- 质量评分由完整性、及时性、合理性、一致性、可追溯性构成，权重后台配置。
- 异常检测先使用明确规则与统计阈值；Demo 中的"AI 识别"需标注为模拟推断。

## 7.2 数据一致性约束

- 所有页面使用同一套源数据和指标服务，禁止为每个页面单独写互相矛盾的数字。
- 总排放 = 各能源排放之和；校区和建筑汇总与学校总量一致，允许因未分摊公共项产生可解释差异。
- 异常影响量、建议节电量、减排量和配额缺口之间可复算。
- 所有模拟价格、因子、配额和目标均标注来源类型与"演示参数"。
- 四层控制塔各层级数据同源：L1 宏观指标 = L2 各部门之和 = L3 各楼栋/设备之和，L4 留存全量原始凭证。
- AI 智能分析中心的预测结果基于上述同源数据，预测值必须与实绩分开标注。

## 10.2 边界条件

### 业务边界

- 一期仅服务北京市重点碳排放高校，不覆盖医院和通用公共机构。
- 核算边界为法人边界内的固定设施，不含 Scope 3 和项目级碳足迹。
- 配额交易仅模拟方案，不连接真实交易系统。
- AI 输出为辅助建议，不替代人工审批、核算和核查。

### 技术边界

- Demo 使用模拟数据，不涉及真实设备协议和网关。
- "实时监测"在 Demo 中指小时/日级模拟数据展示近实时效果。
- 并发能力仅保证演示场景（≥ 20 用户），不保证生产级高可用。

### 数据边界

- 所有排放因子、配额、价格及政策期限按年度配置，禁止硬编码。
- 所有模拟参数标注"演示参数"来源。
- 预测值必须与实绩分开标注，不得混同。
